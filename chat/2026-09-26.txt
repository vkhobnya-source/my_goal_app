```powershell

```

`.env` is excluded from Git. If PostgreSQL was already initialized with the old password, changing `.env` alone won’t change the password stored in that existing database.

```terminaloutput
backend-1  | (Background on this error at: https://sqlalche.me/e/20/e3q8)
```
[Resource link: file:///D:/my_goal_app/docker-compose.yml]

Ассистент: Это, скорее всего, из-за сохранённого тома PostgreSQL: смена `POSTGRES_PASSWORD` в `.env` не меняет пароль уже созданной базы. Ранее в Compose был пароль `postgres`. Обновите пароль в самой базе и в `.env` — данные при этом сохранятся.

В PowerShell из папки `D:\my_goal_app` выполните:

```powershell
docker compose up -d db-prod

$bytes = New-Object byte[] 24
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$newPassword = ([BitConverter]::ToString($bytes) -replace '-', '').ToLowerInvariant()

docker compose exec -e PGPASSWORD=postgres db-prod psql -U postgres -d postgres -c "ALTER ROLE postgres WITH PASSWORD '$newPassword'"
if ($LASTEXITCODE -ne 0) { throw "Не удалось сменить пароль PostgreSQL. Файл .env не изменён." }

$envFile = Join-Path (Get-Location) '.env'
$otherLines = @()
if (Test-Path $envFile) {
    $otherLines = @(Get-Content $envFile | Where-Object { $_ -notmatch '^\s*POSTGRES_PASSWORD\s*=' })
}
$otherLines += "POSTGRES_PASSWORD=$newPassword"
Set-Content -Path $envFile -Value $otherLines -Encoding ascii

docker compose up -d --force-recreate backend
```

Здесь предполагается, что база всё ещё использует прежний пароль `postgres`. Если команда `ALTER ROLE` выдаст ошибку аутентификации, **не удаляйте том** (`docker compose down -v`): это может стереть данные.
